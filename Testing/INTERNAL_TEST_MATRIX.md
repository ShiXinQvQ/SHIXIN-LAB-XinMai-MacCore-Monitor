# SHIXIN LAB · 「芯脉」 MacCore Monitor 0.3.0 Beta 测试矩阵

## 原则

- 每个候选 DMG 都必须先通过自动发布门禁。
- 机器覆盖采用关键组合，不做耗时且收益很低的完整笛卡尔积。
- 不在单台 Mac 上假装覆盖另一种系统版本、散热结构或芯片。
- 任何失败都要记录 App、Helper、macOS、机型、模式、时长和诊断报告。

## 自动发布门禁

执行：

```bash
Scripts/release-public-beta.sh
```

每次必须全部通过：

| 门禁 | 标准 |
|---|---|
| 源码基线 | Git 工作区必须干净；App 内构建来源必须匹配当前完整提交 |
| plist 与三语资源 | 全部通过 `plutil -lint` |
| 当前 SDK | App 与 Helper 的 release 构建通过 |
| 可复现核心逻辑 | `ShixinStressPowerSelfTest --core-only` 非压力自检通过 |
| 双语 PDF | PDF、源 Markdown、生成脚本、图标、版本元数据与法律材料的 SHA-256 清单一致 |
| App | release 构建、版本与 ad-hoc 签名正确 |
| Helper | bundle 内存在、签名正确、版本为 `0.3.0-helper` |
| 第三方材料 | smartctl 存在时，版本、SHA-256、声明与 GPL 文件齐全 |
| DMG | 创建、`hdiutil verify`、只读挂载、卷内签名与结构通过 |
| 校验和 | `.sha256` 生成并回读验证通过 |

自动门禁不会运行真实压力负载，也不会假装覆盖当前机器未安装的 macOS 15.4 SDK。
真实遥测、压力路径和最低系统兼容性分别由下方 M1–M4 真机矩阵验收。

## 关键机器覆盖

| 编号 | 环境 | 必测负载 | 专项检查 |
|---|---|---|---|
| M1 | 当前 macOS + 有风扇 MacBook Pro | CPU/GPU/联合各 1 分钟；联合 5 分钟；联合 30 分钟 | 采样节奏、风扇、手动停止、自动停止、App 退出、CSV、分享图 |
| M2 | macOS 15 + 有风扇 MacBook Pro | CPU/GPU/联合各 1 分钟；联合 5 分钟 | Metal 停止、Helper 安装/更新/修复/卸载、CSV 与分享图 |
| M3 | 当前 macOS + 无风扇 MacBook Air | CPU/GPU/联合各 1 分钟；联合 5 分钟；联合 30 分钟 | 0 RPM/无风扇语义、热状态保护、长测响应性、完整历史曲线 |
| M4 | macOS 15 + 任一 Apple Silicon Mac | 联合 1 分钟 | 最低系统运行门禁、首次打开、Helper、退出清理 |

M4 可以与 M2 是同一台机器。M1 和 M3 必须是不同散热结构。

## 固定场景

| 场景 | 执行位置 | 通过标准 |
|---|---|---|
| 首次 Helper 安装 | M1 或 M2 | 一次授权后可用，版本一致 |
| 旧 Helper 更新 | M2 | 明确提示更新，更新后采样恢复 |
| Helper 修复 | M2 | 不删除历史，socket 与 launchd 恢复 |
| Helper 卸载再安装 | M2 | 卸载后明确降级，重装后恢复 |
| 手动停止 | 每种模式至少一次 | 点击后 1 秒量级停止，不继续占用 CPU/GPU |
| 到时停止 | 1/5/30 分钟 | 正确写入“达到设定时长” |
| App 退出 | M1 | 压力立即停止，历史写入“App 退出清理” |
| 热保护 | M3 或受控热环境 | Serious/Critical 逻辑与设置一致，不要求人为强制达到 Critical |
| 完整 CSV | 每个系统版本 | 文件存在、可打开、字段和样本数量一致 |
| 分享图 | 每个系统版本 | 3200 x 2000，文字不溢出，曲线覆盖完整 Session |
| 历史恢复 | 自动 SelfTest | 损坏主文件可从滚动备份恢复，损坏文件被保留 |

## 采样验收标准

- Helper 首次唤醒允许短暂准备，目标 4 秒内出现第一条可信样本。
- 稳定后新样本中位间隔目标 `0.5–0.7 秒`，P95 小于 `1 秒`。
- 采样缺口必须在历史和分享曲线中断开，不得用曲线跨越伪造趋势。
- 完整 CSV 保留原始样本；历史 JSON 最多保存 900 个全时段代表样本。
- 30 分钟历史曲线必须同时包含测试开头、过程极值和结束时刻。

在装有当前 Helper 的真实测试机执行采样节奏核查：

```bash
swift run ShixinStressPowerSelfTest --sampling-cadence-debug
```

脚本输出首条可信样本耗时、中位间隔和 P95。该结果只代表运行命令的这台真实 Mac，不能替代 M2/M3/M4。

## 结果管理

- 每个候选 DMG 使用独立的结果文件，不覆盖上一候选版本的记录。
- 自动门禁结果与真实设备结果分开标记；`未执行` 不得写成 `通过`。
- 用户侧以 DMG 内双语安装说明和诊断报告为准；维护者的真实设备结果保存在本机，不提交包含设备或个人信息的原始材料。
- 每个失败项附截图、诊断 zip、对应 CSV/分享图文件名；涉及压力停止时记录大致停止耗时。
- 只有 M1、M2、M3 的必测项全部通过，才把固定矩阵标为完成。M4 可与 M2 合并。

## 发布判定

- 自动门禁有任何失败：不得分发。
- M1、M2、M3 未完成：不得标记为“完整多机型矩阵已完成”，但不阻止明确标注为 Beta 的网站/GitHub 分发。
- M4 可与 M2 合并；至少要有一台真实 macOS 15 机器完成运行测试。
- 阻断问题修复后，受影响场景必须重跑；不受影响场景可以沿用同一版本、同一构建的结果。
